Part 01•Human Language & Instructions

What is a Program?

1

Human Language is Recipe-Based: In daily life, we communicate instructions through recipes and steps. Making a cup of tea requires a strict sequence of actions.

2

A Program is Just a Recipe: A computer program is simply a step-by-step sequence of unambiguous instructions written to solve a computational problem.

3

Strict Order Matters: If you pour in the milk before the water has boiled, you ruin the tea. In programming, executing instructions out of order causes bugs or crashes.

The Tea-Making Procedure (Algorithm)
🫖
Step 1: Boil Water
Heat clean water to 100°C (Baseline Input).
🍃
Step 2: Add Tea Leaves
Infuse tea leaves and spices for 3 minutes.
🥛
Step 3: Add Milk & Sugar
Simmer gently to dissolve sugar completely.
☕
Step 4: Strain & Serve
Filter out leaves. Hot tea produced (Output)!
Part 02•The Communication Barrier

The Problem: Computers
Can't Understand Human Words

1

Human Language Has Ambiguity: Words rely heavily on slang, context, and intuition. When you say "make tea", a human uses common sense. A computer has zero intuition.

2

Silicon Only Knows Electricity: A processor consists of microscopic physical transistors. They only understand two electrical states: 0 = OFF (Low Voltage) and 1 = ON (High Voltage).

3

The Early Era: Early programmers had to manually punch holes in paper cards or flip switches to enter raw 0s and 1s directly into mainframes.

The Divide: Human Mind vs. Silicon Machine
Human Language
"Please calculate total price with tax"
Expressive, conceptual, but full of ambiguity.
⬇️ Incompatible ⬇️
Machine Language (Binary)
01001000 01100101 01101100 01110000
Pure electrical voltage states. Unreadable to humans!
💡 "What about ChatGPT?" Modern AI doesn't think in words either; it converts text into mathematical probabilities executed on binary silicon.
Part 03•The Human Bridge

High-Level
Programming Languages

1

Designed for Humans: High-level languages allow us to write computer logic using familiar English words like if, while, and print.

2

Massive Productivity: Writing 1 single line of high-level code replaces dozens of tedious machine instructions, drastically reducing bugs and mistakes.

3

Portability Across Devices: High-level code can run on Intel PCs, Apple MacBooks, and smartphones without having to re-engineer code for each processor's unique wiring.

Goal: Print "Hello, World!" to the screen
❌ Low-Level Machine Assembly: 12 tedious lines 
section .data
    msg db 'Hello, World!', 0xa
section .text
    global _start
_start:
    mov edx, 14
    mov ecx, msg
    mov ebx, 1
    mov eax, 4
    int 0x80
    mov eax, 1
    int 0x80
✅ High-Level Python: 1 simple, readable line 
print("Hello, World!")
Part 04•The Translation Process

Compilers vs.
Interpreters

1

The Need for a Translator: Because computers can only execute binary 0s and 1s, we need a translator program to turn our high-level code into machine instructions.

2

Compiler (Like a Published Book): Translates the entire program all at once upfront into a standalone binary file (.exe on Windows). Examples: C, C++, Rust.

3

Interpreter (Like a Live Translator): Reads and runs the source code line-by-line in real time. Examples: Python, JavaScript.

Part 06•Standard Output

The print() Function: Giving Code a Voice

1

Speaking to the Screen: print() is the fundamental tool used to display text, messages, or results on the terminal display.

2

Multiple Items: Commas print multiple items with an automatic space separator: print("Score:", 95, "points").

3

Escape Sequences (Special Formatting):

  • \n drops down to a New Line.
  • \t inserts a Tab space (indents text).
  • \" prints a literal quotation mark inside strings.

4

Code Comments (#): Notes for humans that Python ignores — on their own line or after code. Remember: making mistakes and seeing red errors is a completely normal part of coding!

Part 07•Data Storage

Variables: The
Labeled Storage Containers

1

The Kitchen Jars Analogy: In your kitchen, you have jars labeled "Salt", "Sugar", and "Pepper". Each jar has space inside and a distinct label on the outside.

2

Memory with a Name Tag: In computer RAM, a variable is a named storage slot where data is held so the program can find and reuse it later.

3

The Assignment Operator (=): The single equals sign means store this inside that container: salt = "Sea Salt".

4

Values Can Be Replaced: Just like refilling an empty sugar jar, you can change a variable's value anytime (score = 10, then later score = 25).

Part 08•Syntax Rules

Rules for Naming
Variables in Python

1

Allowed Characters Only: Letters (a-z), numbers (0-9), and underscores (_). No spaces and no special symbols.

2

Cannot Start with a Number: Must begin with a letter or underscore. player1 is valid ✅, but 1player is an error ❌.

3

Case-Sensitive: age, Age, and AGE are three completely separate variables.

4

No Python Keywords: You cannot use reserved command words as names (like if, while, for, class, True).

Quick Reference: Valid vs. Invalid Names
✅ Valid Names
user_age
total_score
player_1
_secret_key
❌ Invalid Names
user age (space)
1st_place (number first)
total-score (hyphen)
while (keyword)
🐍 Python Style Convention: Use lowercase words separated by underscores (snake_case), e.g., student_name.
⚠️ Note: print is a built-in function, not a keyword — so print = 5 is legal but shadows the real print. Always avoid it!
Part 09•Classifying Information

Data Types:
What Kind of Stuff Goes Inside?

1

Why Types Matter: You wouldn't pour hot soup into an envelope! A computer must know what category data belongs to so it knows what operations are allowed.

2

The Fundamental Types:

  • str (String): Text wrapped in quotes ("Alice", 'Tea').
  • int (Integer): Whole numbers (25, -5, 100).
  • float (Floating-Point): Decimal numbers (9.99, 3.14).

3

Automatic Detection: Python is dynamically typed—it figures out the type automatically from the value you store.

Crucial Contrast: Numbers vs. Text
1. Integers (Numbers do Math):
5 + 5 ➔ 10
Calculates mathematical sum.
2. Strings (Quotes glue text together):
"5" + "5" ➔ "55"
Concatenates (glues) characters together.
💡 Putting quotation marks around any number turns it into plain text!
🔍 Try it yourself: type(5) → <class 'int'>, type("5") → <class 'str'>

Only Two States in the Universe: A Boolean (bool) is the simplest data type in computing. It can only ever hold one of two values: True or False.

Part 11•User Interaction

The input() Function: Listening to the User

1

A Two-Way Conversation: While print() talks, input() listens. It pauses the program and waits for the user to type and press Enter.

2

The Golden Rule: It's Always a String: Everything that comes from input() is saved as text (str)—even if the user types 20!

3

Converting to Numbers (Type Casting): If you want to do arithmetic with user input, you must convert it using int(): age = int(input("Enter your age: "))

How input() Works in Code
1. Prompt the User:
name = input("What is your name? ")
Program halts and waits for keystrokes...
2. Convert Input for Math:
birth_year = int(input("Birth year: "))
Wraps input in int() so the value is a real number!
3. Print the Result:
print(f"Hello {name}, born in {birth_year}!")
No hardcoded "current year" — the output never goes stale!

What is a Token? Just like sentences in English are constructed from nouns, verbs, adjectives, and punctuation, every line of Python is broken down into Tokens — the smallest individual units of code.

Part 14•Calculations

Arithmetic Operators:
Doing Math in Python

1

Standard Operations: Addition (+), Subtraction (-), and Multiplication (*) behave just like a standard calculator.

2

The Division Difference:

  • / (True Division): Always gives a decimal float (10 / 2 = 5.0).
  • // (Floor Division): Divides and rounds down to the nearest whole number (10 // 3 = 3).

3

Modulus (%) & Power (**):

  • % returns the remainder: 10 % 3 = 1. (Used to check even/odd numbers!).
  • ** calculates exponents: 2 ** 3 = 8 (2 to the power 3).

Arithmetic Cheat Sheet
▸ ⏸️ Pause & Predict: 17 // 5 = ?   17 % 5 = ?   2 ** 4 = ?
17 // 5 = 3  |  17 % 5 = 2  |  2 ** 4 = 16
💡 Pro Tip: Any number num % 2 == 0 is Even; otherwise, it is Odd!
⚠️ Floor gotcha: // rounds down, even for negatives: -7 // 2 = -4 (not -3!)
Part 15•Comparisons

Comparison Operators:
Asking Yes/No Questions

1

Always Return Booleans: Relational operators compare two values and always evaluate to either True or False.

2

Equal To (==) vs Assignment (=):

  • = (Single equals): Stores a value into a variable (x = 5).
  • == (Double equals): Tests equality: 5 == 5 is True, but 5 == 3 is False.

3

Not Equal To (!=): Reads as "not-equal" — it asks "Are these two values DIFFERENT?" (Python's own word for flipping truth values is not — next slide!)

  • 5 != 2 is True (they differ), while 5 != 5 is False (they match).

4

Real-Life Application: age >= 18 (Voting), total > 50 (Free shipping), role != "banned" (Access).

Relational Operators Reference
💡 Type Trap: "5" == 5 evaluates to False because a text string is not a number!
⌨️ How to Type: != is typed as ! (Shift + 1) followed by =.
❓ Why not <>? In SQL, Excel, and legacy Python 2, <> was used. In modern Python 3, <> was removed and raises a SyntaxError. Modern Python strictly uses !=.
⚠️ Caution: Never write if age = 18! That causes a SyntaxError. Always use == to check equality.
Part 16•Decision Logic

Logical Operators:
Combining Conditions

1

Connecting Multiple Truths: Often, one comparison is not enough. You need to verify multiple conditions at once before making a decision.

2

The Three Core Logical Words:

  • and: Returns True only if BOTH conditions are True.
  • or: Returns True if AT LEAST ONE condition is True.
  • not: Flips / Inverts the truth value (not True becomes False).

3

Real-Life App Decisions:

  • Ride Rollercoaster: height >= 120 and age >= 10
  • Discount Day: is_student or is_senior
  • Access Allowed: not is_account_suspended

The Truth Tables
not simply inverts: not True → False  |  not False → True
Worked Examples in Action 
age = 20
has_license = True
can_drive = (age >= 18) and has_license  # Result: True
is_raining = True
go_outside = not is_raining  # Result: False
Part 17•Variable Updating

Assignment Operators:
Storing & Updating Data

1

The Foundation (=): Assigns whatever is evaluated on the right-hand side into the variable container on the left (score = 10).

2

Compound / Augmented Assignment: In programming, we frequently update a variable based on its existing value (e.g. score = score + 5). Python provides a clean shortcut: score += 5.

3

Every Arithmetic Operator Has a Twin:

  • +=, -=, *=, /=
  • //= (floor divide), %= (remainder), **= (power)

Compound Assignment Reference (Initial x = 10)
💡 Why use them? It prevents bugs from misspelling long variable names twice (e.g. user_total_score += 10).
Part 18•Special Operations

Membership & Identity:
Presence & Memory Check

1

Membership (in, not in): Tests whether a value or letter exists inside a collection or sequence (like text, lists, tuples).

2

Identity (is, is not): Checks if two variables refer to the exact same object in computer memory (RAM), not just equal values.

3

The Crucial Difference (== vs is):

  • ==: Do they look identical? (Value Equality)
  • is: Are they the same physical address in RAM? (Identity)

Membership: in / not in Checking sequences 
# Check substring:
"chai" in "masala chai"             # Result: True

# Check item not in list:
"admin" not in ["guest", "editor"]  # Result: True
Identity: is / is not (RAM Check) Memory address 
list1 = [1, 2, 3]
list2 = [1, 2, 3]
list1 == list2  # True  (values look identical)
list1 is list2  # False (two distinct boxes in RAM!)
💡 Pro Tip: Use x is None to check whether a variable was never set (holds None) — not to test for empty values!
Part 19•Code Foundations

Expressions:
Producing Values in Code

1

What is an Expression? An expression is any piece of code that the Python interpreter evaluates to produce a value (the value might even be None).

2

The Assignment Test: An expression is anything that can sit on the right-hand side of an assignment operator (=)!

3

Expressions Nest Within Expressions:

  • (7 - 3) * 0.5 → Produces 2.0
  • (7 - 3) → Produces 4
  • 7 → A single literal number is an expression!

The "Right-Hand Side" Golden Rule
variable = <EXPRESSION>
If Python can compute it into a value to store, it is an expression!
result = (7 - 3) * 0.5
Produces 2.0
result = (7 - 3)
Produces 4
result = 7
Produces 7
🎯 Summary: Expressions compute; values are born. Software runs by continuously evaluating expressions!
Part 20•Building Expressions

Anatomy of Expressions:
Types & Building Blocks

1

The 4 Building Blocks: Every expression is built by combining: Variables, Values (Literals), Operators, and Functions.

2

Expression vs. Statement:

  • x = 5 + 3 contains an Expression (5 + 3 produces 8).
  • print(x) is a Statement (executes an action on screen).

3

Functions inside Expressions: Function calls like round(3.5) or relational checks like x == 1 are full valid expressions!

4 Common Expression Types in Python

Part 21•Calculation Rules

Operator Precedence:
The Order of Operations

1

Who Goes First? When multiple operators appear in a single expression (e.g. 2 + 3 * 4), Python follows strict precedence rules (PEMDAS / BODMAS).

2

The Precedence Hierarchy:

  1. Parentheses ( ): Always first! (Highest priority)
  2. Exponentiation **: Powers
  3. Multiplication & Division *, /, //, %: Left-to-right
  4. Addition & Subtraction +, -: Left-to-right
  5. Comparisons ==, >=, etc.: Evaluated next
  6. Logical Operators: not → and → or (Lowest priority)

3

The Golden Rule: When in doubt, use parentheses! They remove all ambiguity for both Python and human readers.

Step-by-Step Evaluation Example
▸ ⏸️ Pause & Predict: what does x become below?
x = 21.0 — and it's a float! (4 / 2 makes it so)
Original Expression:
x = 5 + 2 * 3 ** 2 - (4 / 2)
Step 1 (Parentheses): (4 / 2) → 2.0
5 + 2 * 3 ** 2 - 2.0
Step 2 (Exponent): 3 ** 2 → 9
5 + 2 * 9 - 2.0
Step 3 (Multiplication): 2 * 9 → 18
5 + 18 - 2.0
Step 4 (Add & Subtract): 5 + 18 - 2.0
Final Result: 21.0
🔬 Bonus gotcha: ** groups right-to-left, so 2 ** 3 ** 2 = 512 (not 64)!
Part 22•Data Flexibility

Type Conversion:
Changing Data Types

1

Why Convert Types? Python is strongly typed—it refuses to do incompatible actions (like "Score: " + 95 → TypeError). We convert types to make them work together.

2

Implicit Conversion (Automatic): Python automatically converts a smaller type to a wider type to prevent data loss: 5 + 2.5 → 7.5 (int automatically became float)

3

Explicit Conversion (Type Casting): Manually convert data using Python's built-in type functions: int(), float(), str(), bool().

Type Casting Functions in Action
int("42")  →  42
String to Integer
float("3.14")  →  3.14
String to Float
str(95)  →  "95"
Integer to String
bool(1)  →  True  |  bool(0)  →  False
Truthy / Falsy
A real error in the wild (totally normal!):
>>> "Score: " + 95
TypeError: can only concatenate str (not "int") to str
⚠️ Common Pitfall: int("hello") raises a ValueError — no digits to convert!
⚠️ Sneaky one: int("3.14") also fails — use float("3.14") first, then int() if needed.
